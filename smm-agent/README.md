# SMM Agent

ИИ-агент, который ежедневно готовит черновик поста для VK-сообщества: придумывает тему, пишет текст и генерирует изображение — и ставит запись как **отложенную**, чтобы человек успел проверить её перед публикацией.

## Как это работает

Агент — это цикл (`agent/core.py`), который раз в день (или по команде) проходит шаги:

1. **plan** — проверяет память (SQLite): черновик на завтра уже подготовлен? Если да — завершает работу без действий (защита от дублей при повторном запуске).
2. **act (тема)** — `YandexGPTTool.choose_topic()`: модель выбирает новую тему, избегая тех, что уже использовались (берёт последние 20 тем из памяти).
3. **act (текст)** — `YandexGPTTool.generate_post_text()`: генерирует живой текст поста с эмодзи и хэштегами, без markdown-разметки.
4. **act (изображение)** — `YandexARTTool.generate_image()`: асинхронно генерирует изображение по теме (запуск операции → поллинг результата).
5. **act (публикация черновика)** — `VKTool`: загружает изображение на стену сообщества и создаёт запись с `publish_date` в будущем (завтра, в `PUBLISH_HOUR`). Такая запись **не публикуется сразу** — она попадает в раздел «Отложенные записи» сообщества VK, где администратор может её посмотреть, отредактировать или отменить до момента публикации.
6. **observe** — запоминает тему, текст и `post_id` в SQLite, но только после успешного создания записи в VK. Если что-то сломалось на шагах 3–5 — память не обновляется, следующий запуск повторит попытку.

## Почему черновик — это отложенная запись VK, а не отдельный канал ревью

VK API (`wall.post`) сам поддерживает отложенные записи через параметр `publish_date`. Это даёт готовый интерфейс проверки прямо в VK — без необходимости строить email/Telegram-уведомления для ревью.

## Память

`agent/memory.py` хранит в SQLite таблицу `posts` — тему, текст, `vk_post_id` и дату публикации каждого созданного черновика. Используется для:
- избежания повторов тем (`recent_topics`);
- идемпотентности — не создавать второй черновик на ту же дату при повторном запуске (`has_post_for`).

## Переменные окружения

См. `env.example`. Ключевые:

- `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` — доступ к YandexGPT и YandexART.
- `VK_ACCESS_TOKEN` — ключ доступа сообщества VK с правами `wall`, `photos` (Управление сообществом → Работа с API).
- `VK_GROUP_ID` — ID сообщества (без минуса).
- `PUBLISH_HOUR` — час, на который ставится отложенная запись (по умолчанию 12).
- `SCHEDULE_HOUR`, `SCHEDULE_MINUTE`, `TIMEZONE` — расписание запуска самого агента (по умолчанию 9:00 Europe/Moscow).

## Запуск

Локально:

```bash
cp env.example .env   # заполнить своими значениями
pip install -r requirements.txt

python main.py --once   # один проход цикла агента (для проверки/ручного запуска)
python main.py          # планировщик — ежедневный запуск по расписанию
```

В Docker:

```bash
docker build -t smm-agent .
docker run --env-file .env -v $(pwd)/data:/data smm-agent
```

## Стек

- Python 3.11
- YandexGPT (REST API) — генерация темы и текста поста
- YandexART (REST API, асинхронная генерация) — изображение к посту
- VK API (`photos.*`, `wall.post`) — загрузка изображения и отложенная публикация
- APScheduler — ежедневное расписание
- SQLite — память между запусками

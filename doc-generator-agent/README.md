# Doc Generator Agent

ИИ-агент, который автоматически генерирует и поддерживает в актуальном состоянии `README.md` и подробную документацию (`docs/DOCUMENTATION.md`) целевого репозитория — на основе анализа его кода.

## Как это работает

Агент — это ReAct-цикл (`agent/core.py`), который раз в день (или по команде) проходит шаги:

1. **observe** — узнаёт текущий HEAD целевой ветки репозитория через GitHub API.
2. **plan** — сравнивает с памятью (SQLite): код менялся с прошлой генерации? Если нет — завершает работу без действий.
3. **act (анализ)** — строит «карту проекта» (`agent/scanner.py`): обходит дерево файлов, разбирает `.py`-файлы через `ast` и извлекает docstring'и, классы и сигнатуры функций (без тел — экономим контекст модели), читает значимые конфиги (requirements.txt, Dockerfile и т.п.) и текущие README/документацию.
4. **act (генерация)** — отправляет карту проекта в YandexGPT (`agent/tools.py`, `YandexGPTTool`) и получает обновлённые `README.md`, `docs/DOCUMENTATION.md` и описание для Pull Request. Модель обновляет существующие файлы, а не переписывает их с нуля.
5. **act (публикация)** — создаёт ветку `docs/auto-update-<sha>`, коммитит изменения и открывает Pull Request в целевую ветку (`GitHubTool`). Агент никогда не пишет напрямую в основную ветку.
6. **observe** — запоминает SHA обработанного коммита в SQLite, но только после успешного создания PR. Если публикация не удалась — следующий запуск повторит попытку.

## Память

`agent/memory.py` хранит в SQLite одну запись на репозиторий — SHA последнего коммита, на который была сгенерирована документация. Это позволяет агенту пропускать запуски без изменений в коде и не открывать пустые PR.

## Переменные окружения

См. `env.example`. Ключевые:

- `GITHUB_TOKEN` — токен с правами на запись (`repo`) в целевой репозиторий: нужен и на чтение кода, и на создание веток/коммитов/PR.
- `TARGET_REPO`, `TARGET_BRANCH` — какой репозиторий и какую ветку документировать.
- `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` — доступ к YandexGPT.
- `DOC_PATH` — путь к файлу подробной документации в целевом репозитории.
- `SCHEDULE_HOUR`, `SCHEDULE_MINUTE`, `TIMEZONE` — расписание ежедневного запуска.

## Запуск

Локально:

```bash
cp env.example .env   # заполнить своими значениями
pip install -r requirements.txt

python main.py --once   # один проход цикла агента (для проверки/ручного запуска)
python main.py          # планировщик — ежедневный запуск по расписанию
```

В Docker:

```bash
docker build -t doc-generator-agent .
docker run --env-file .env -v $(pwd)/data:/data doc-generator-agent
```

## Стек

- Python 3.11
- PyGithub — работа с GitHub API (чтение кода, ветки, коммиты, Pull Request)
- YandexGPT (через REST API) — генерация текста документации
- APScheduler — ежедневное расписание
- SQLite — память между запусками
